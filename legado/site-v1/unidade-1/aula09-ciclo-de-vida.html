Ciclo de Vida: Construtores, Destrutores e RAII

🎯 Objetivos
  • Compreender todos os tipos de construtores em C++
  • Usar listas de inicialização corretamente
  • Entender a ordem de construção e destruição
  • Aplicar RAII como idioma fundamental
🎵
Sintonia — v0.2 — AudioBuffer com ciclo de vida

Implementamos audio_buffer com construtor parametrizado, de cópia e de movimento. A regra do zero em ação: std::vector gerencia tudo.

§1

Tipos de Construtores

cpp Todos os construtores de audio_buffer 
class audio_buffer {
public:
    // 1. Padrão — cria buffer vazio
    audio_buffer() noexcept = default;

    // 2. Parametrizado — cria buffer de tamanho n
    explicit audio_buffer(std::size_t n, float sr = 44100.0f)
        : data_(n, 0.0f), sample_rate_{sr}  // lista de inicialização
    {
        if (sr <= 0.0f)
            throw std::invalid_argument("sample_rate deve ser positivo");
    }

    // 3. Cópia — regra do zero: compilador gera corretamente
    audio_buffer(const audio_buffer&) = default;

    // 4. Movimento — eficiente: transfere sem copiar dados
    audio_buffer(audio_buffer&&) noexcept = default;

    // 5. Destrutor — regra do zero: vector limpa automaticamente
    ~audio_buffer() = default;
private:
    std::vector data_;
    float sample_rate_ = 44100.0f;
};
§2

Listas de Inicialização

cpp Por que lista de inicialização, não assignment 
// ❌ Ineficiente: default-inicializa e depois atribui
audio_buffer::audio_buffer(std::size_t n, float sr) {
    data_ = std::vector(n, 0.0f); // cópia extra!
    sample_rate_ = sr;
}

// ✅ Correto: inicializa diretamente
audio_buffer::audio_buffer(std::size_t n, float sr)
    : data_(n, 0.0f),   // constrói data_ com n zeros
      sample_rate_{sr}  // {} inicialização uniforme
{ }

// Ordem de inicialização: SEMPRE a ordem de declaração na classe
// (não a ordem da lista — isso é uma armadilha!)
⚠️
Armadilha da ordem de inicialização

A lista de inicialização executa na ordem em que os membros foram declarados na classe, não na ordem em que aparecem na lista. Se um membro depende de outro, declare-os na ordem correta.

§3

RAII — Resource Acquisition Is Initialization

cpp RAII em ação: recurso adquirido no construtor 
// Sem RAII (estilo C — perigoso)
void processar(const std::string& path) {
    FILE* f = fopen(path.c_str(), "r");
    // Se lançar exceção aqui → LEAK
    processa(f);
    fclose(f);    // pode não executar
}

// Com RAII (estilo C++ — seguro)
void processar(const std::string& path) {
    std::ifstream f{path};      // abre no construtor
    if (!f) throw std::runtime_error{"não abriu"};
    processa(f);
    // f.~ifstream() fecha automaticamente — mesmo com exceção
}

// audio_buffer usa RAII: data_ (vector) é adquirido no construtor
// e liberado no destrutor — zero código manual

LLMs neste Tópico

🤖
Prompt sugerido

"Implemente em C++17 uma classe RAII que gerencia uma conexão a um banco de dados SQLite. Deve abrir no construtor, fechar no destrutor, e não permitir cópia (mas permitir movimento). Convenções: snake_case, noexcept onde aplicável."

⚠️
O que o LLM costuma errar

LLMs frequentemente esquecem noexcept no destrutor e no construtor de movimento, e confundem 'delete por cópia' com 'não-copiável'. Sem noexcept no move, std::vector não usará movimento.
