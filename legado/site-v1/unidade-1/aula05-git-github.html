Aula 05 · 12/mai

Git e GitHub como Ambiente de Trabalho

🎯 Objetivos
  • Usar Git para versionar código C++ (branches, commits, .gitignore)
  • Colaborar via pull requests no GitHub
  • Configurar GitHub Actions para build automático
  • Trabalhar com o repositório do Sintonia como exemplo
§1

Fluxo de Trabalho Básico

bash Comandos fundamentais do dia a dia 
# Clonar o repositório do Sintonia
git clone https://github.com/dobidu/sintonia.git && cd sintonia

# Ver estado do repositório
git status        # o que mudou?
git diff          # o que exatamente mudou?
git log --oneline # histórico compacto

# Criar branch para uma feature
git switch -c feature/aula-08-exercicios

# Adicionar e commitar
git add include/sintonia/sample.hpp src/sample.cpp
git commit -m "feat(sample): adiciona set_amplitude com validação"

# Enviar para o GitHub
git push origin feature/aula-08-exercicios
💡
Commits atômicos e descritivos

Cada commit deve fazer uma coisa só. Mensagem no formato tipo(escopo): descrição. Tipos: feat, fix, docs, test, refactor, chore.

§2

,.gitignore para Projetos C++

bash Arquivo .gitignore do Sintonia 
# Build
build/
cmake-build-*/
CMakeFiles/
*.o  *.a  *.so  *.out

# IDE
.vscode/
.idea/
*.swp

# Dados sensíveis
*.db
submissions/

# macOS
.DS_Store
⚠️
Nunca versione arquivos compilados

Binários mudam a cada compilação, criam conflitos impossíveis de resolver e incham o repositório. O .gitignore do Sintonia já está configurado corretamente.

§3

GitHub Actions para C++

yaml ci.yml — o que já existe no Sintonia 
name: CI
on: [push, pull_request]
jobs:
  build-and-test:
    runs-on: ubuntu-22.04
    steps:
      - uses: actions/checkout@v4
      - name: CMake configure
        run: cmake -B build -DCMAKE_BUILD_TYPE=Debug
      - name: Build
        run: cmake --build build --parallel
      - name: Tests
        run: ctest --test-dir build --output-on-failure

O CI roda automaticamente a cada push. Se os 72 testes passarem, o PR pode ser mergeado.

🤖

LLMs neste Tópico

🤖
Prompt sugerido

"Gere um arquivo .gitignore completo para um projeto C++17 com CMake, VS Code e CLion. Inclua comentários explicando cada seção. Não inclua entradas desnecessárias."

⚠️
O que o LLM costuma errar

LLMs geram .gitignore genéricos demais (com entradas para Java, Python, etc.) ou incompletos (esquecendo arquivos de sanitizer ou de IDE específica). Sempre revise e simplifique.

Ex.

Exercícios Propostos

01.Clone o repositório do Sintonia, crie uma branch aluno/{seu-nome}, adicione seu nome em CONTRIBUTORS.md (crie o arquivo se não existir), faça commit e abra um Pull Request.
02.Configure o GitHub Actions no seu próprio repositório fork do Sintonia. Quebre um teste propositalmente, faça push e observe o CI falhar. Corrija e faça o CI passar novamente.
03.Use git bisect para encontrar o commit que introduz um bug (o professor criará um histórico de demonstração com um bug plantado).
04.Configure um hook de pre-commit que roda clang-format --dry-run --Werror antes de cada commit, impedindo commits com código mal formatado.
