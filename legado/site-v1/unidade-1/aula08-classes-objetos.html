Classes e Objetos em C++

🎯 Objetivos

  • Compreender o papel do ponteiro this
  • Aplicar const-correctness em métodos, parâmetros e variáveis

🎵
Sintonia v0.1 — sample e track

Hoje criamos as primeiras classes do Sintonia: sample (amostra de áudio individual) e track (sequência de amostras). O código está em include/sintonia/sample.hpp.

§1

Separação de Interface e Implementação

Em C++, a convenção é separar a declaração (o contrato) em .hpp e a definição (a implementação) em .cpp. Isso reduz tempo de recompilação e esconde detalhes de implementação.

cpp sample.hpp — interface pública 
#pragma once
#include <stdexcept>

// Representa uma única amostra de áudio com amplitude em [-1.0, 1.0]
class sample {
public:
    // Constante da classe — compartilhada, sem custo de instância
    static constexpr float MAX_AMP = 1.0f;

    sample() noexcept = default;   // construtor padrão: amplitude 0
    explicit sample(float amplitude, float sample_rate = 44100.0f);

    // Getters — todos const: não modificam o objeto
    float amplitude()   const noexcept { return amplitude_; }
    float sample_rate() const noexcept { return sample_rate_; }
    bool  is_silent()   const noexcept { return amplitude_ == 0.0f; }

    // Setter com validação
    void set_amplitude(float a);

    // Operadores (implementados em sample.cpp)
    sample& operator+=(const sample& rhs) noexcept;
    sample& operator*=(float factor)      noexcept;

private:
    float amplitude_   = 0.0f;      // sufixo _ = membro privado
    float sample_rate_ = 44100.0f;
};
💡
Boa prática: #pragma once

Use #pragma once em vez de include guards (#ifndef). É mais simples, sem risco de typos, e suportado por todos os compiladores modernos.

§2

Modificadores de Acesso

ModificadorQuem pode acessarUso típico
publicQualquer códigoInterface: construtores, getters, operadores
privateApenas a própria classeDados internos, métodos auxiliares
protectedPrópria classe + derivadasDados que subclasses precisam acessar
⚠️
Regra de ouro

Comece tudo como private. Torne public apenas o necessário para o contrato da classe. Use protected somente ao projetar herança — e mesmo assim prefira getters/setters a dados diretamente protegidos.

§3

Const-Correctness

Marque como const tudo que não deve ser modificado. O compilador verifica isso em tempo de compilação — é documentação executável.

cpp As formas de const
▶ playground 
// 1. Método const: garante que NÃO modifica o objeto
float sample::amplitude() const { return amplitude_; }

// 2. Parâmetro const&: eficiente (sem cópia) + somente leitura
void print_sample(const sample& s) {
    std::cout << s.amplitude() << "\n";
    // s.set_amplitude(0.5f);  // ERRO: s é const
}

// 3. Variável const: não pode ser reatribuída
const float MAX_RATE = 192000.0f;

// 4. Objeto const: só pode chamar métodos const
const sample s{0.5f};
s.amplitude();       // OK — método const
// s.set_amplitude(0.3f); // ERRO de compilação ← detecta bug!
§4

O Ponteiro this e Interface Fluente

Dentro de qualquer método não-estático, this é um ponteiro implícito para o objeto receptor. Raramente precisamos usá-lo explicitamente — mas é útil para desambiguação e para construir interfaces fluentes.

cpp Interface fluente com this 
class track {
public:
    // Retorna *this → permite encadeamento de chamadas
    track& set_name(const std::string& name) {
        name_ = name;
        return *this;
    }
    track& set_gain(float gain) {
        gain_ = gain;
        return *this;
    }
    track& set_muted(bool m) {
        muted_ = m;
        return *this;
    }
private:
    std::string name_;
    float gain_  = 1.0f;
    bool  muted_ = false;
};

// Uso idiomático — encadeamento de chamadas:
track t;
t.set_name("baixo").set_gain(0.8f).set_muted(false);

§5

Membros static

Membros static pertencem à classe, não a instâncias individuais. Uma variável estática é compartilhada por todos os objetos da classe; um método estático pode ser chamado sem criar um objeto.

cpp Contador de instâncias com static 
// sample.hpp
class sample {
public:
    static int live_count() noexcept { return count_; }
    static constexpr float DEFAULT_RATE = 44100.0f;

    sample() { ++count_; }
    ~sample() { --count_; }
    // ...
private:
    static int count_;   // compartilhado por TODAS as instâncias
    float amplitude_ = 0.0f;
};

// sample.cpp — definição obrigatória para static não-constexpr
int sample::count_ = 0;

// Uso:
std::cout << sample::live_count() << "\n"; // 0 — sem criar objeto
{
    sample a{0.5f}, b{-0.3f};
    std::cout << sample::live_count() << "\n"; // 2
}
std::cout << sample::live_count() << "\n"; // 0 — destruídos

Prompt de modelagem de classe

"Preciso de uma classe audio_buffer em C++17 para o projeto Sintonia. Convenções: snake_case, identificadores em inglês, comentários em português. Requisitos: armazena samples como std::vector<float>; construtor parametrizado (size_t, float); métodos operator[] const e não-const com verificação de limites; size(), sample_rate() const; clear() noexcept; sem new/delete crus. Gere audio_buffer.hpp e audio_buffer.cpp."

⚠️
O que o LLM provavelmente vai errar

Sem instrução explícita, o LLM provavelmente vai: (1) usar PascalCase (AudioBuffer), (2) esquecer noexcept onde caberia, (3) não incluir versão const de operator[]. Revise sempre.

Exercícios Propostos

01. Implemente a classe track do Sintonia v0.1 com: vector<sample> samples_, float sample_rate_, string name_. Adicione add_sample(sample), size() const, operator[](size_t) const. Separe em .hpp e .cpp.

03. Adicione um membro static a sample que conta o número de instâncias vivas. Escreva um teste no main() que cria 3 samples, imprime o contador, destrói um usando escopo ({ }) e imprime novamente.
04. Explique com código concreto por que o compilador recusa chamar um método não-const em um objeto const. O que acontece internamente? Como isso detecta bugs em tempo de compilação?
