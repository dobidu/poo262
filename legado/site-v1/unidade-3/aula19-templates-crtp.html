Templates de Função e Classe

cpp Template de classe — buffer 
// C++17: static_assert para restringir T (sem concepts)
template 
class buffer {
    static_assert(std::is_arithmetic::value,
                  "buffer: T deve ser tipo aritmético");
public:
    explicit buffer(std::size_t n, float sr = 44100.0f);

    T& operator[](std::size_t i);
    const T& operator[](std::size_t i) const;

    // Template membro: converte para outro tipo
    template 
    buffer convert_to(float scale = 1.0f) const;

    std::size_t size()        const noexcept;
    float       sample_rate() const noexcept;
private:
    std::vector data_;
    float          sample_rate_;
    template  friend class buffer; // acesso entre instâncias
};

// Instâncias: cada uma é uma classe diferente em compilação
buffer   fp32{1024, 44100.0f};
buffer pcm16{1024, 44100.0f};
auto converted = fp32.convert_to(32767.0f);

CRTP — Polimorfismo Estático sem vtable

cpp CRTP no Sintonia v2.0 — examples/v20_templates/ 
// Base template: conhece o tipo derivado em compilação
template 
class static_effect {
public:
    // Chamada resolvida em compilação — zero overhead de vtable
    void process(buffer& b) {
        static_cast(this)->process_impl(b);
    }
    std::string name() const {
        return static_cast(this)->name_impl();
    }
};

class static_gain : public static_effect {
public:
    explicit static_gain(float f) : factor_{f} {}
    void process_impl(buffer& b) {
        b.apply([this](float s) { return s * factor_; });
    }
    std::string name_impl() const { return "StaticGain"; }
private:
    float factor_;
};

// Função template: aceita qualquer static_effect sem vtable
template 
void apply_to(Effect& eff, buffer& b) {
    eff.process(b);  // resolvido em compilação
}

Estático vs. Dinâmico: Trade-offs

AspectoPolimorfismo DinâmicoPolimorfismo Estático (CRTP)
Overhead1 indireção por chamadaZero (inlined pelo compilador)
Tamanho do binárioMenor (1 cópia)Maior (instanciado para cada T)
Tempo de compilaçãoRápidoLento (para muitos tipos)
Extensibilidade runtimeSim (plugins)Não (tipos fixos em compilação)
Uso típicoCadeia de efeitos, pluginsProcessamento de buffer, DSP

LLMs neste Tópico

🤖
Prompt sugerido

"Implemente um template C++17 ring_buffer<T, N> de tamanho fixo em compilação (N como parâmetro não-tipo). Inclua push, pop, peek, size, empty. Use static_assert para N > 0."

⚠️
O que o LLM costuma errar

LLMs com templates frequentemente: (1) usam concepts C++20 quando o requisito é C++17, (2) declaram a implementação em .cpp em vez de .hpp (templates precisam estar visíveis), (3) esquecem a especialização parcial necessária para void.
