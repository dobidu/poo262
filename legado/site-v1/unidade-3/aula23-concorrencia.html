Concorrência: std::thread, mutex e lock_guard

🎯 Objetivos
  • Criar e sincronizar threads com std::thread e std::mutex
  • Usar std::lock_guard e std::unique_lock para RAII de locks
  • Identificar race conditions e deadlocks
  • Conhecer std::async e std::future
§1

Thread e Mutex

cpp Produção paralela de buffers de áudio 
#include 
#include 
#include 

class multi_track_renderer {
    std::mutex results_mutex_;
    std::vector rendered_;

public:
    // Renderiza N tracks em paralelo
    std::vector render_all(const std::vector& tracks) {
        std::vector threads;
        rendered_.resize(tracks.size());

        for (std::size_t i = 0; i < tracks.size(); ++i) {
            threads.emplace_back([this, &tracks, i] {
                auto buf = tracks[i].render();  // independente — sem lock

                std::lock_guard lock{results_mutex_}; // RAII
                rendered_[i] = std::move(buf);
                // lock liberado automaticamente ao sair do escopo
            });
        }

        for (auto& t : threads) t.join();  // espera todas terminarem
        return std::move(rendered_);
    }
};
⚠️
Race condition — sutil e perigoso

Acessar rendered_[i] sem o mutex seria uma race condition: múltiplas threads lendo/escrevendo a mesma memória simultaneamente → comportamento indefinido. Compile com -fsanitize=thread para detectar.

std::async e std::future

// std::async: lança em thread separada, retorna future
auto future_buf = std::async(std::launch::async, [&track]() {
    return track.render();  // executa em background
});

// Faz outro trabalho enquanto a thread processa...
do_other_work();

// Bloqueia aqui até o resultado estar pronto
audio_buffer result = future_buf.get();

// parallel_transform manual para processar M buffers em N threads
std::vector> futures;
for (const auto& t : tracks)
    futures.push_back(std::async(std::launch::async,
                                 [&t]{ return t.render(); }));

std::vector results;
for (auto& f : futures)
    results.push_back(f.get());

LLMs neste Tópico

🤖
Prompt sugerido

"Implemente um processador de áudio multi-thread em C++17 que processa N arquivos WAV em paralelo usando std::async. Garanta: sem race conditions, sem deadlocks, liberação de recursos mesmo com exceções."

⚠️
O que o LLM costuma errar

LLMs frequentemente introduzem deadlocks ao usar múltiplos mutexes (locking em ordem diferente em threads diferentes) ou esquecem de chamar join(). Sempre compile com -fsanitize=thread.

Exercícios Propostos

04.Implemente um pool de threads reutilizável (thread_pool) que processa tarefas de renderização de áudio. Use std::condition_variable para sincronização.
