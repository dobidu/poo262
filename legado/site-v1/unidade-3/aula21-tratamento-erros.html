Tratamento de Erros: Exceções, optional e variant

🎯 Objetivos
  • Criar hierarquias de exceções semânticas
  • Usar std::optional para resultados que podem falhar
  • Usar std::variant para tipos alternativos
  • Decidir entre exceções, optional e código de retorno
🎵
Sintonia — v2.1 — Erros modernos

wav_reader::load() retorna std::optional<vector<float>>: falhas esperadas sem exceção. Veja extras/wav-io/wav_reader.hpp.

§1

Hierarquia de Exceções

cpp Hierarquia semântica de exceções do Sintonia 
#include 
#include 

// Base: todos os erros do Sintonia
class sintonia_error : public std::runtime_error {
public:
    explicit sintonia_error(const std::string& msg)
        : std::runtime_error{"[Sintonia] " + msg} {}
};

// Erros específicos — capturáveis individualmente
class file_error   : public sintonia_error {
    using sintonia_error::sintonia_error;
};
class format_error : public sintonia_error {
    using sintonia_error::sintonia_error;
};
class audio_error  : public sintonia_error {
    using sintonia_error::sintonia_error;
};

// Captura em cascata (específico primeiro)
try {
    auto buf = wav_reader::load_or_throw("input.wav");
} catch (const format_error& e) {
    std::cerr << "Formato inválido: " << e.what() << "\n";
} catch (const file_error& e) {
    std::cerr << "Arquivo não encontrado: " << e.what() << "\n";
} catch (const sintonia_error& e) {
    std::cerr << "Erro Sintonia: " << e.what() << "\n";
}
§2

optional e variant

cpp optional para falha esperada; variant para tipos alternativos 
#include 
#include 

// optional: sucesso ou ausência — sem informação de erro
std::optional wav_reader::load(const std::string& path) noexcept {
    try {
        wav_reader r{path};
        return r.read_as_buffer();
    } catch (...) {
        return std::nullopt;  // qualquer falha → nullopt
    }
}

// Uso com optional:
auto result = wav_reader::load("input.wav");
if (result) {
    process(*result);          // deref segura
} else {
    std::cerr << "Falha ao carregar\n";
}
// Ou: result.value_or(audio_buffer{}) — com fallback

// variant: um de N tipos alternativos
using load_result = std::variant;  // buffer ou mensagem de erro

load_result load_with_error(const std::string& path) noexcept {
    try {
        wav_reader r{path};
        return r.read_as_buffer();
    } catch (const std::exception& e) {
        return std::string{e.what()};  // retorna o erro como string
    }
}

// Uso com variant:
std::visit([](auto&& v) {
    using T = std::decay_t;
    if constexpr (std::is_same_v)
        process(v);
    else
        std::cerr << "Erro: " << v << "\n";
}, load_with_error("input.wav"));
§3

Quando Usar Cada Abordagem

SituaçãoAbordagemRazão
Erro verdadeiramente excepcional (bug, corrupção)ExceçãoPropaga pela pilha automaticamente
Falha esperada sem informação de errostd::optionalEficiente, sem overhead de exceção
Falha esperada com informação de errostd::variant ou expectedTipo no retorno força tratamento
Performance crítica (hot path)Código de retorno ou optionalSem stack unwinding
API de biblioteca públicaoptional ou expectedNão força exceções em callers

LLMs neste Tópico

🤖
Prompt sugerido

"Refatore wav_reader::load para retornar std::variant<audio_buffer, std::string> em vez de lançar exceções. Mostre como o chamador trata ambos os casos com std::visit."

⚠️
O que o LLM costuma errar

LLMs frequentemente: confundem std::optional com nullable pointer, esquecem que std::visit precisa ser exaustivo (cobrir todos os tipos), e não mencionam std::expected (C++23) como alternativa.

Exercícios Propostos

01.Refatore sample::set_amplitude() para usar std::optional<sample> como retorno em vez de lançar std::domain_error. Quando cada abordagem é mais adequada?
02.Implemente uma função parse_config(std::string_view) que retorna std::variant<Config, ParseError>. Use std::visit para tratar os dois casos.
03.Compare o overhead de exceção vs. optional em um loop de 1M iterações onde 10% das operações falham. Use std::chrono e interprete os resultados.
04.Implemente std::expected<audio_buffer, std::string> manualmente (polyfill) usando std::variant e operador * para acessar o valor de sucesso.
