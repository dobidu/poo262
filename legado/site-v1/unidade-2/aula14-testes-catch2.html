Os 72 testes do repositório Sintonia usam Catch2 v3. Execute: ctest --test-dir build --output-on-failure

§1

Estrutura de Testes Catch2

cpp TEST_CASE, SECTION, REQUIRE — padrões idiomáticos 
#include 
#include 
#include "sintonia/audio_buffer.hpp"

using Catch::Approx;

TEST_CASE("audio_buffer: construção básica", "[audio_buffer][construção]") {
    // Arrange
    audio_buffer buf{512, 44100.0f};

    // Assert — REQUIRE falha e para o teste
    REQUIRE(buf.size()        == 512);
    REQUIRE(buf.sample_rate() == Approx(44100.0f));
    REQUIRE(buf.peak_level()  == Approx(0.0f));
}

TEST_CASE("audio_buffer: semântica de cópia", "[audio_buffer][cópia]") {
    audio_buffer original{4, 44100.0f};
    original[0] = 0.5f;

    SECTION("cópia é independente do original") {
        auto copia = original;
        copia[0] = 0.9f;               // modifica a cópia
        REQUIRE(original[0] == Approx(0.5f));  // original inalterado
    }

    SECTION("cópia tem mesmos valores") {
        auto copia = original;
        REQUIRE(copia[0] == Approx(0.5f));
    }
}
§2

Tipos de Asserção

MacroComportamentoQuando usar
REQUIRE(expr)Falha → para o TEST_CASEPré-condições, estado básico
CHECK(expr)Falha → continua o testeVerificações independentes
REQUIRE_THROWS_AS(expr, tipo)Requer exceção do tipo exatoValidação de erros
REQUIRE_NOTHROW(expr)Requer que não lanceOperações seguras
Approx(v)Comparação float com tolerânciaQualquer float/double
cpp Exemplos de uso 
// Float: sempre use Approx
REQUIRE(buf.rms_level() == Approx(0.707f).epsilon(0.001));

// Exceção do tipo correto
REQUIRE_THROWS_AS(buf[9999], std::out_of_range);

// Não lança
REQUIRE_NOTHROW(buf.clear());

// CHECK: continua após falha (útil para múltiplas verificações)
CHECK(buf.size()        == 512);
CHECK(buf.sample_rate() == Approx(44100.0f));
§3

Integração CMake e CI

cmake CMakeLists.txt — configuração dos testes 
# FetchContent baixa Catch2 automaticamente
FetchContent_Declare(Catch2 GIT_REPOSITORY https://github.com/catchorg/Catch2.git
                              GIT_TAG v3.5.2)
FetchContent_MakeAvailable(Catch2)

add_executable(sintonia_tests
    tests/test_sample.cpp
    tests/test_audio_buffer.cpp)
target_link_libraries(sintonia_tests PRIVATE sintonia_core Catch2::Catch2WithMain)

# Registra testes no CTest (permite ctest e CI)
include(Catch)
catch_discover_tests(sintonia_tests)

ctest -R audio_buffer roda só testes com 'audio_buffer' no nome. ./sintonia_tests '[sample]' filtra por tag Catch2.

Prompt sugerido

"Gere testes Catch2 v3 para a classe track do Sintonia. Cubra: construção, render com ganho, render silenciada, render com efeito, semântica de cópia e movimento. Use Approx para floats e REQUIRE_THROWS_AS para erros."

⚠️
O que o LLM costuma errar

LLMs esquecem: Approx para floats, a versão const de métodos, testes de exceção com o tipo correto, e testes de estado de objetos movidos. Verifique que cada SECTION é independente.

Exercícios Propostos

01.Escreva testes Catch2 para wav_reader de extras/wav-io/. Cubra: load de arquivo existente, load de arquivo inexistente (optional), round-trip write→read.
02.Aplique TDD: escreva primeiro os testes para uma nova função audio_buffer::trim_silence(float threshold) que remove silêncio do início e fim. Depois implemente a função.
03.Configure o filtro de tags no CMakeLists.txt para criar suítes separadas: [unit] (roda rápido, sem I/O) e [integration] (pode ser lento). Adicione as tags nos testes existentes.
04.Meça a cobertura de testes usando gcov/lcov. Identifique quais branches do corrector.py — digo, do effect_chain — não estão cobertos e escreva testes para eles.
