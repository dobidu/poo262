Aula 18 · 02/jul

Polimorfismo Dinâmico: vtables, RTTI e dynamic_cast

🎯 Objetivos
  • Compreender o mecanismo interno de vtable e vptr
  • Usar RTTI e dynamic_cast com segurança
  • Contrastar polimorfismo dinâmico com estático (templates)
  • Identificar quando RTTI é sinal de design problemático
§1

Mecanismo de vtable/vptr

cpp O que o compilador gera internamente 
// Você escreve:
class effect {
    virtual void process(audio_buffer& buf) = 0;
    virtual std::string name() const = 0;
};

// O compilador gera (conceptualmente):
struct effect_vtable {
    void (*process)(effect*, audio_buffer&);  // ponteiro para process()
    std::string (*name)(const effect*);       // ponteiro para name()
};

struct effect_internal {
    const effect_vtable* vptr;  // PRIMEIRO membro: ponteiro para a vtable
    // ... outros membros
};

// Quando você chama e->process(buf):
// 1. Carrega e->vptr (ponteiro para vtable do tipo real)
// 2. Busca na vtable o ponteiro de process()
// 3. Chama o ponteiro — overhead: 1 indireção de memória
ℹ️
Custo do polimorfismo virtual

Cada objeto com virtual tem um vptr (8 bytes em x64). Cada chamada virtual tem 1 indireção de memória. Em hot loops de áudio (44100 samples/s), isso importa — use CRTP (Aula 19) quando o desempenho é crítico.

§2

dynamic_cast e RTTI

cpp Downcast seguro com dynamic_cast 
// dynamic_cast verifica o tipo em tempo de execução (RTTI)
effect* e = get_some_effect();  // tipo real desconhecido

// Para ponteiro: retorna nullptr se falhar
if (auto* g = dynamic_cast(e)) {
    std::cout << "Factor: " << g->factor() << "\n";
    // g é válido aqui
}

// Para referência: lança std::bad_cast se falhar
try {
    gain_effect& g = dynamic_cast(*e);
    // g é válido aqui
} catch (const std::bad_cast& ex) {
    // não era um gain_effect
}

// typeid: obtém informação de tipo em runtime
std::cout << typeid(*e).name() << "\n";  // nome mangled
⚠️
dynamic_cast é sinal de design ruim

Se você precisa de dynamic_cast com frequência, sua hierarquia provavelmente viola OCP ou ISP. A solução é adicionar o método necessário à interface base, ou usar o padrão Visitor.
