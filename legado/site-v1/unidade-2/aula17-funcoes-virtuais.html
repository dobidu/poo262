Aula 17 · 30/jun

Funções Virtuais, override, final e Abstração

🎯 Objetivos
  • Usar virtual, override e final corretamente
  • Criar classes abstratas com funções puramente virtuais
  • Compreender o mecanismo de vtable/vptr
  • Distinguir polimorfismo em tempo de compilação vs. execução
§1

virtual, override e final

cpp Hierarquia com override e final 
class effect {
public:
    virtual void process(audio_buffer& buf) = 0; // pura virtual → abstrata
    virtual std::string name() const { return "effect"; } // virtual com implementação
    virtual ~effect() = default;
};

class gain_effect : public effect {
public:
    void process(audio_buffer& buf) override { // override: compilador verifica
        buf *= factor_;
    }
    std::string name() const override { return "Gain"; }
    // final: impede subclasses de sobrescrever
    float factor() const noexcept final { return factor_; }
private:
    float factor_;
};

// ❌ Sem override — typo silencioso:
class reverb_bad : public effect {
    void Process(audio_buffer&) { }  // P maiúsculo — nova função, não override!
    // Compilador não avisa sem override
};
💡
Sempre use override

override faz o compilador verificar que você está realmente sobrescrevendo um método virtual da base. Sem ele, um typo cria uma nova função silenciosamente.

§2

Classes Abstratas

cpp Classes abstratas e interfaces em C++ 
// Classe abstrata: tem pelo menos um método puramente virtual
class effect {
    virtual void process(audio_buffer&) = 0;  // = 0 → pura virtual
    // NÃO pode ser instanciada: effect e{};  ← ERRO
};

// Interface pura: apenas métodos virtuais puros, sem estado
class recordable {
public:
    virtual void start_recording() = 0;
    virtual void stop_recording()  = 0;
    virtual bool is_recording() const noexcept = 0;
    virtual ~recordable() = default;  // destrutor virtual mesmo em interface
};

// Implementação concreta: implementa TODOS os puros
class looper : public oscillator, public sampler, public recordable {
public:
    void start_recording() override { is_rec_ = true; }
    void stop_recording()  override { is_rec_ = false; }
    bool is_recording()    const noexcept override { return is_rec_; }
    void generate(std::vector&, float) override;
private:
    bool is_rec_ = false;
};

LLMs neste Tópico

🤖
Prompt sugerido

"Projete uma hierarquia de plugins de áudio em C++17 com: interface audio_plugin (pura virtual), classe abstrata effect_plugin (implementa partes comuns), e três concretas. Use override, final onde apropriado."

⚠️
O que o LLM costuma errar

LLMs frequentemente: declaram override sem virtual na base (erro de compilação), usam final em classes quando deveriam usar em métodos, e não fornecem a implementação do destrutor virtual.

Ex.

Exercícios Propostos

01.Remova todos os override de gain_effect no Sintonia. Introduza um typo no nome de um método. Compile — o compilador avisa? Recoloque os override e veja a diferença.
02.Crie uma classe abstrata filter com métodos virtuais puros process() e reset(). Implemente low_pass_filter e high_pass_filter. Escreva testes Catch2.
03.Meça o overhead do polimorfismo virtual: chame process() via ponteiro base (dinâmico) e via método direto (estático) em um loop de 10M iterações. Qual é a diferença?
04.Implemente um método describe() não-virtual na classe base que chama o virtual name(). Demonstre o padrão Template Method: a base orquestra, as derivadas especializam.
