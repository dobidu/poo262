Aula 16 · 25/jun

Herança Múltipla e o Problema do Diamante

🎯 Objetivos
  • Usar herança múltipla de interfaces sem ambiguidades
  • Compreender o problema do diamante e suas consequências
  • Resolver o diamante com herança virtual
  • Contrastar com Java/C# (interfaces únicas, herança simples)
🎵
Sintonia v1.4 — Looper com diamante

Hoje criamos looper: herda de oscillator E sampler, que herdam virtualmente de sound_source. Código completo em extras/diamond-inheritance/diamond.hpp.

§1

O Problema do Diamante

O diamante ocorre quando uma classe herda de duas classes que compartilham uma ancestral comum. Sem virtual, a classe mais derivada recebe duas cópias dos membros da ancestral — criando ambiguidade.

cpp Sem virtual — duas cópias de sound_source em looper 
class sound_source { public: std::string name_; };

class oscillator : public sound_source { /* ... */ };
class sampler    : public sound_source { /* ... */ };

class looper : public oscillator, public sampler {
    // looper tem DUAS cópias de sound_source:
    // - oscillator::sound_source::name_
    // - sampler::sound_source::name_
};

looper lp;
lp.name_ = "x";  // ERRO DE COMPILAÇÃO: ambiguous!
// Qual name_ ? oscillator::sound_source::name_
//              ou sampler::sound_source::name_ ?
§2

Solução: Herança virtual

Ao usar virtual na herança, garantimos que sound_source aparece uma única vez em looper, independentemente do número de rotas de herança.

cpp extras/diamond-inheritance/diamond.hpp — Sintonia v1.4 
class sound_source {
public:
    explicit sound_source(std::string name) : name_{std::move(name)} {}
    virtual void generate(std::vector<float>& buf, float sr) = 0;
    virtual ~sound_source() = default;
    const std::string& name() const { return name_; }
protected:
    std::string name_;
};

// "virtual" aqui: sound_source será compartilhada
class oscillator : public virtual sound_source {
public:
    explicit oscillator(std::string name)
        : sound_source{std::move(name)} {}
    void generate(std::vector<float>& buf, float sr) override;
};

class sampler : public virtual sound_source {
public:
    explicit sampler(std::string name)
        : sound_source{std::move(name)} {}
    void generate(std::vector<float>& buf, float sr) override;
};

// Looper herda UMA instância de sound_source
class looper : public oscillator, public sampler, public recordable {
public:
    // ⚠️ Com herança virtual: looper (classe mais derivada)
    //    DEVE inicializar a base virtual diretamente
    explicit looper(std::string name)
        : sound_source{std::move(name)},  // ← inicializa a base virtual
          oscillator{name_},
          sampler{name_}
    {}

    // Sem ambiguidade — sound_source existe apenas uma vez
    void generate(std::vector<float>& buf, float sr) override {
        if (is_recording_)
            oscillator::generate(buf, sr);
        else
            sampler::generate(buf, sr);
    }
    // ...
};
⚠️
Responsabilidade da classe mais derivada

Com herança virtual, looper é responsável por construir sound_source, mesmo não herdando diretamente dela. Os construtores de oscillator e sampler não inicializam a base virtual — esse papel cabe a looper.

§3

Ordem de Construção e Destruição

text Saída ao construir e destruir um looper 
looper lp{"meu_looper"};

# Construção (base virtual primeiro):
[+] sound_source("meu_looper")  ← base virtual — UMA VEZ
[+] oscillator
[+] sampler
[+] looper

# Destruição (ordem inversa):
[-] ~looper
[-] ~sampler
[-] ~oscillator
[-] ~sound_source("meu_looper")  ← UMA VEZ

Compare: sem herança virtual, sound_source apareceria duas vezes na construção e destruição — e os dados seriam duplicados em memória.

§4

Contraste com Java e C#

Java e C# eliminam o problema proibindo herança múltipla de classes concretas. Em compensação, permitem implementar múltiplas interfaces — que são equivalentes às classes puramente abstratas de C++. Na prática, a maioria dos usos legítimos de herança múltipla em C++ envolve apenas interfaces puras.

cpp Herança segura — apenas de interfaces puras (sem diamante) 
// Interface pura — sem estado, sem diamante
class recordable {
public:
    virtual void start_recording() = 0;
    virtual void stop_recording()  = 0;
    virtual bool is_recording() const noexcept = 0;
    virtual ~recordable() = default;
};

class playable {
public:
    virtual void play()  = 0;
    virtual void pause() = 0;
    virtual ~playable() = default;
};

// Herdar de múltiplas interfaces puras: seguro, sem diamante
class looper : public oscillator, public sampler, public recordable {
    // oscillator e sampler usam herança virtual com sound_source
    // recordable é interface pura — sem estado duplicado
};
🤖

LLMs e Herança Múltipla

🤖
LLMs frequentemente erram aqui

Ao pedir ao LLM uma hierarquia com diamante, ele muitas vezes:

  • Esquece o virtual na herança intermediária
  • Não inicializa a base virtual no construtor da classe mais derivada
  • Gera código que compila mas produz comportamento indefinido

Sempre compile com -Wall e teste a ordem de construção imprimindo mensagens nos construtores.

💡
Prompt para testar o LLM

"Implemente em C++17 uma hierarquia de diamante: sound_source (base virtual), oscillator e sampler (herança virtual de sound_source), looper (herda de oscillator e sampler). Adicione mensagens nos construtores e destrutores. Mostre que sound_source é construída apenas uma vez."

Ex.

Exercícios Propostos

01. Compile e execute extras/diamond-inheritance/test_diamond.cpp. Observe a saída dos construtores. Remova virtual das heranças de oscillator e sampler e tente compilar — o que acontece?
02. Adicione um segundo atributo a sound_source (ex.: float volume_). Sem herança virtual, demonstre (com sizeof) que looper teria duplicado o atributo. Com herança virtual, mostre que o tamanho é o esperado.
03. Java não tem herança múltipla de classes, mas permite múltiplas interfaces. Pesquise o padrão Mixin em C++ usando herança múltipla de classes com implementação. Como ele difere do diamante? Dê um exemplo que não causa problema.
04. Implemente sinusoidal_oscillator : public oscillator e file_sampler : public sampler. Crie loop_synth : public sinusoidal_oscillator, public file_sampler. Verifique que compila e que a construção de sound_source ocorre uma única vez.
