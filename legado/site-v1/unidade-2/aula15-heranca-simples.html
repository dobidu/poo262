Herança Simples: is-a, Reutilização e Especialização

🎯 Objetivos
  • Distinguir herança (is-a) de composição (has-a)
  • Implementar hierarquias com proteção de acesso correta
  • Compreender ordem de construção e destruição na herança
  • Decidir quando herança é a escolha errada
🎵
Sintonia — v1.0 — Hierarquia effect

Hoje criamos a hierarquia effect → gain_effect/reverb_effect/delay_effect. A versão com bug (sem destrutor virtual) está em extras/broken-designs/v1.0-no-virtual-dtor/.

§1

is-a vs. has-a

RelaçãoQuando usarImplementação C++Exemplo Sintonia
is-a (herança)B é um tipo de A; substitui Aclass B : public Again_effect é um effect
has-a (composição)B usa A internamentemembro por valor/ptrtrack tem um audio_buffer
uses-a (dependência)B usa A apenas temporariamenteparâmetro de métodoprocess(audio_buffer&)
⚠️
Herança não é para reuso de código

A razão certa para herdar é o polimorfismo: poder tratar gain_effect como effect via ponteiro base. Se você quer só reutilizar código, prefira composição ou funções livres.

§3

O Destrutor Virtual — Obrigatório

cpp Por que o destrutor DEVE ser virtual 
// ❌ BUG: sem virtual ~effect()
class effect {
    ~effect() { }  // não-virtual!
};
// Deleting via base pointer → ~effect() only, not ~gain_effect()
effect* e = new gain_effect{0.5f};
delete e;  // UNDEFINED BEHAVIOR: destrutor do gain_effect não é chamado

// ✅ CORRETO: virtual ~effect() = default
class effect {
    virtual ~effect() = default;  // garante chamada do destrutor mais derivado
};
💡
Regra: se tem virtual, o destrutor é virtual

Toda classe com pelo menos um método virtual deve ter destrutor virtual. Verifique no extras/broken-designs/v1.0-no-virtual-dtor/ o efeito sem ele.

LLMs neste Tópico

🤖
Prompt sugerido

"Implemente a hierarquia sound_effect com três derivadas: chorus_effect, compressor_effect e eq_effect. Cada uma processa um audio_buffer. Use destrutor virtual, override, clone(). C++17, snake_case."

⚠️
O que o LLM costuma errar

LLMs frequentemente: esquecem o destrutor virtual, declaram membros protected desnecessariamente (quebrando encapsulamento), e não implementam clone() corretamente (slicing silencioso).
