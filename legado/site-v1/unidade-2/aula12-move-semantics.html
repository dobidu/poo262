Aula 12 · 11/jun

Semântica de Movimento: rvalues e std::move

🎯 Objetivos
  • Distinguir lvalues de rvalues
  • Implementar construtor e atribuição de movimento
  • Usar std::move corretamente
  • Compreender NRVO e quando o compilador otimiza
🎵
Sintonia — v1.2 — audio_buffer com movimento

Adicionamos construtor de movimento a audio_buffer. Retornar um buffer de render() agora é gratuito via NRVO.

§1

lvalue vs. rvalue

cpp Identificando lvalues e rvalues 
// lvalue: tem nome, endereço, pode aparecer à esquerda de =
int x = 42;        // x é lvalue
std::string s = "hello"; // s é lvalue

// rvalue: temporário, sem nome, não pode aparecer à esquerda de =
42              // literal → rvalue
x + 1           // expressão temporária → rvalue
std::string{"world"}  // temporário → rvalue

// Referência a rvalue — captura temporários
std::string&& r = std::string{"tmp"};  // estende o lifetime do temporário

// Consequência para audio_buffer:
audio_buffer buf{1024, 44100.0f};
audio_buffer copia = buf;             // lvalue → cópia (caro: aloca + copia)
audio_buffer moved = std::move(buf);  // rvalue → movimento (barato: só troca ponteiros)
§2

Implementando o Movimento

cpp Construtor e atribuição de movimento 
class audio_buffer {
    std::vector data_;
    float sample_rate_;
public:
    // ✅ noexcept: sem noexcept, std::vector nunca usará movimento ao realocar!
    audio_buffer(audio_buffer&& other) noexcept
        : data_{std::move(other.data_)},
          sample_rate_{other.sample_rate_}
    {
        other.sample_rate_ = 0.0f;  // deixar other num estado válido mas "vazio"
        // other.data_ já está vazio — vector garante isso após move
    }

    audio_buffer& operator=(audio_buffer&& other) noexcept {
        if (this != &other) {        // auto-atribuição: raro mas possível
            data_        = std::move(other.data_);
            sample_rate_ = other.sample_rate_;
            other.sample_rate_ = 0.0f;
        }
        return *this;
    }
};
⚠️
std::move não move nada!

std::move(x) apenas faz um cast para rvalue reference. O movimento real acontece no construtor/atribuição que recebe o rvalue. Após std::move(x), x está num estado válido mas indeterminado — não use mais.

§3

NRVO — Named Return Value Optimization

cpp NRVO: retorno eficiente sem movimento explícito 
// track::render() retorna audio_buffer por valor
// NRVO: o compilador constrói o resultado DIRETAMENTE no destino
audio_buffer track::render() const {
    audio_buffer out{buffer_};     // cópia necessária (buffer_ preservado)
    out *= gain_;
    effects_.process(out);
    return out;                    // NRVO: sem movimento extra no return
}

// Na chamada:
auto result = track.render();  // result é construído diretamente — zero cópias extras

// Para garantir NRVO: retornar SEMPRE a mesma variável local
// NÃO retornar via if/else diferentes variáveis: quebra NRVO

LLMs neste Tópico

🤖
Prompt sugerido

"Implemente uma função merge_buffers que combina N audio_buffers em um, maximizando eficiência com semântica de movimento. Mostre por que o retorno por valor é eficiente em C++17."

⚠️
O que o LLM costuma errar

LLMs frequentemente adicionam std::move no return de variáveis locais: isso DESABILITA o NRVO. O compilador moderno já otimiza o retorno. Não escreva return std::move(local);.
