Smart Pointers: unique_ptr, shared_ptr, weak_ptr

🎯 Objetivos
  • Usar unique_ptr para propriedade exclusiva

  • Detectar e quebrar ciclos de referência

🎵
Sintonia — v1.1 — Cadeia de efeitos com unique_ptr

effect_chain usa vector<unique_ptr<effect>>: propriedade exclusiva, destruição automática, sem vazamentos.

§1

unique_ptr — Propriedade Exclusiva

cpp unique_ptr na cadeia de efeitos 
#include 

class effect_chain {
    std::vector> effects_;
public:
    // Recebe propriedade — chamador não pode mais usar o ponteiro
    void add(std::unique_ptr e) {
        effects_.push_back(std::move(e));  // move, não copia
    }

    // Factory method idiomático
    template
    void emplace(Args&&... args) {
        effects_.push_back(std::make_unique(std::forward(args)...));
    }
};

// Uso
effect_chain chain;
chain.add(std::make_unique(0.5f));  // make_unique: sem new
chain.emplace(0.3f, 0.2f);        // ainda mais idiomático

shared_ptr e weak_ptr

cpp Ciclo de referência e como quebrá-lo com weak_ptr 
// Problema: ciclo → vazamento mesmo com shared_ptr
struct node {
    std::shared_ptr next;  // ciclo: A→B→A → nunca destroem
};

// Solução: weak_ptr não incrementa contagem de referências
struct project_node {
    std::shared_ptr child;
    std::weak_ptr   parent;  // weak: não impede destruição
};

// Verificar se weak_ptr ainda é válido
void use_parent(std::weak_ptr wp) {
    if (auto sp = wp.lock()) {  // lock() → shared_ptr ou nullptr
        // sp é válido aqui
    }
    // fora do if: sp liberado automaticamente
}

Prompt sugerido

"Tenho um design onde audio_engine possui tracks (unique_ptr), e tracks precisam observar configurações globais sem possuir o objeto de configuração. Modele isso em C++17 com os smart pointers corretos."

⚠️
O que o LLM costuma errar

LLMs tendem a usar shared_ptr em excesso (mais fácil de explicar) quando unique_ptr + referência seria correto. Pergunte sempre: 'quem é o dono?'
