01

STL: contêineres, algoritmos e iteradores

┌──┤▸ DERIVA · v2.3 - o inventário da sonda├─────────┐

A sonda passa a carregar peças, em include/deriva/inventario.hpp e src/inventario.cpp. O que faz os algoritmos valerem a pena ali é a capacidade: sem limite, guardar é push_back e pronto; com limite, aparecem as perguntas que a STL responde em uma linha - o que cabe, qual é a peça mais pesada, quantas satisfazem um critério, quanto de folga sobra.

Toda pergunta que o inventário responde sai de um algoritmo com lambda, e o único laço escrito à mão que sobra no arquivo é o do despejo, que percorre para formatar texto. É essa proporção que é o argumento da aula.

┌──┤✓ DICA · O padrão é vector, e a exceção se justifica├─────────┐

Na maioria dos casos std::vector é o contêiner certo, e a razão é a memória contígua: o processador lê a linha de cache inteira, de forma que percorrer é rápido mesmo quando a complexidade assintótica diz o contrário. Troque por outro quando tiver a operação frequente medida, e não pela tabela de O grande.

A coluna da direita é mais útil do que parece: metade das linhas diz nenhum uso, e isso é informação. Um sistema de vinte classes atravessa o semestre com vector, deque, set e string, e é bom saber disso antes de escolher a estrutura pelo nome mais interessante.

03

Algoritmos e lambdas no inventário

Uma lambda é um objeto com operator() que o compilador escreve para você, e a lista de captura é a lista de membros dele. Isso explica o comportamento inteiro: capturar por valor copia para dentro do objeto, capturar por referência guarda uma referência que vive tanto quanto o escopo de origem, e é por isso que lambda guardada fora do escopo tem de capturar por valor.

Em inventario.cpp as lambdas são todas locais, e as que capturam capturam por referência, porque morrem na mesma expressão em que nascem. Já em estrategia_de_patrulha, na Aula 25, a lambda é devolvida e sobrevive à chamada que a criou, de forma que a captura por valor deixa de ser preferência e passa a ser obrigação - é a armadilha de tempo de vida do std::string_view da Aula 3, noutra roupa.

Os algoritmos aparecem seis vezes no arquivo, e cada um carrega uma lição própria. Em std::accumulate, o zero inicial define o tipo da soma, e passar 0.0 daria soma em double sem ninguém pedir. Em std::max_element, a faixa vazia devolve end(), e desreferenciar o iterador de fim é comportamento indefinido, de forma que a comparação com end() não é cerimônia. Em std::count_if, o predicado vem de fora por std::function, e é isso que torna a função útil sem saber o que se vai perguntar.

┌──┤▲ ATENÇÃO · std::sort é instável, e o replay cobra├─────────┐

ordenar_por_massa desempata pelo rótulo, e o desempate não é capricho: std::sort não promete preservar a ordem de entrada entre elementos equivalentes, de forma que sem o desempate a ordem entre massas iguais seria a que o algoritmo quisesse, e o despejo deixaria de ser byte a byte igual entre execuções. A condição 3 do portão falharia, e falharia de forma intermitente.

Quem quer estabilidade sem desempate usa std::stable_sort, e paga por ela em memória. O material escolheu o desempate explícito porque ele documenta o critério de ordem, que stable_sort deixa implícito na ordem de inserção.

└──────────┘
┌──┤✓ DICA · std::clamp, e o retorno por referência├─────────┐

O construtor de inventario usa std::clamp de C++17 para prender a capacidade numa faixa, no lugar do par std::min e std::max aninhado, que obriga a ler duas chamadas encaixadas para descobrir a intenção.

std::clamp devolve referência const ao argumento escolhido, e aí está a armadilha: alimentá-lo com temporário e guardar o resultado por referência deixa uma referência pendurada. No Deriva o resultado é copiado para um int, e é isso que o torna seguro.

└──────────┘

O idioma erase-remove fecha a lista, e ele é o mais estranho da STL: std::remove_if não remove nada, apenas empurra o que sobrevive para a frente e devolve o novo fim, e é o erase do contêiner que corta. Em C++20 a mesma coisa é std::erase_if, uma chamada só - e o material nomeia o idioma antigo em vez de fingir que ele é natural, porque quem lê código de C++17 vai encontrá-lo.

┌──┤▲ ATENÇÃO · O que o modelo costuma errar├─────────┐

Modelos tendem ao laço manual quando a versão com algoritmo seria mais clara, e é preciso pedir explicitamente que não haja laço para ver se conseguem. O segundo erro é mais caro: sobre contêiner de std::unique_ptr, eles produzem cópia onde só pode haver movimento, e o código não compila; o terceiro é esquecer o desempate, e devolver ordem que muda entre execuções.

`clamp` devolve **referência**, e é a armadilha dele: não o alimente com temporário guardando o resultado por referência. Aqui o valor é copiado para um `int`, e é isso que o torna seguro.

cppsrc/inventario.cpp · std::clamp em vez de min/max aninhado
inventario::inventario(int capacidade) noexcept
    // `std::clamp` no lugar do min/max aninhado: a capacidade fica entre 0 e
    // 999 sem que ninguém precise ler duas chamadas encaixadas para saber
    // disso. Cuidado com o retorno por referência - aqui o resultado é
    // copiado para um `int`, e é isso que o torna seguro.
    : capacidade_(std::clamp(capacidade, 0, 999)) {}

`remove_if` empurra para o fim e devolve o novo fim; `erase` corta. Em C++20 seria `std::erase_if`, uma chamada só - e é por isso que o material nomeia o idioma antigo em vez de fingir que ele é natural.

cppsrc/inventario.cpp · erase-remove
std::size_t inventario::descartar_se(
    const std::function<bool(const componente&)>& criterio) {
  // Erase-remove. Em C++20: std::erase_if(pecas_, ...), uma chamada.
  const auto novo_fim = std::remove_if(
      pecas_.begin(), pecas_.end(),
      [&criterio](const std::unique_ptr<componente>& c) { return criterio(*c); });
  const std::size_t saiu = static_cast<std::size_t>(pecas_.end() - novo_fim);
  pecas_.erase(novo_fim, pecas_.end());
  return saiu;
}
✓ COMPILA · exemplos/deriva/src/inventario.cpp:51 · abrir no Compiler Explorer · -std=c++17 -Wall -Wextra

`std::sort` é instável. Sem o desempate pelo rótulo, a ordem entre massas iguais seria a que o algoritmo quisesse, e o despejo deixaria de ser determinístico.

cppsrc/inventario.cpp · o desempate que o replay exige
void inventario::ordenar_por_massa() {
  std::sort(pecas_.begin(), pecas_.end(),
            [](const std::unique_ptr<componente>& a,
               const std::unique_ptr<componente>& b) {
              // Desempate pelo rótulo: sem ele, a ordem entre massas iguais
              // seria a que o `sort` quisesse, e o despejo deixaria de ser
              // determinístico - o replay quebraria.
              if (a->massa() != b->massa()) return a->massa() > b->massa();
              return a->rotulo() < b->rotulo();
            });
}
✓ COMPILA · exemplos/deriva/src/inventario.cpp:62 · abrir no Compiler Explorer · -std=c++17 -Wall -Wextra

Passar `0.0` daria soma em `double` sem ninguém pedir, e o truncamento apareceria três capítulos depois.

cppsrc/inventario.cpp · o zero que define o tipo da soma
int inventario::massa_total() const {
  // `accumulate` com lambda: o zero inicial é `int`, e é ele que define o tipo
  // da soma. Passar `0.0` daria soma em double sem ninguém pedir.
  return std::accumulate(pecas_.begin(), pecas_.end(), 0,
                         [](int soma, const std::unique_ptr<componente>& c) {
                           return soma + c->massa();
                         });
}

A função serve sem saber o que se vai perguntar, e é isso que a torna útil - acrescentar um critério não a edita.

std::size_t inventario::contar_se(
    const std::function<bool(const componente&)>& criterio) const {
  return static_cast<std::size_t>(std::count_if(
      pecas_.begin(), pecas_.end(),
      [&criterio](const std::unique_ptr<componente>& c) { return criterio(*c); }));

`max_element` devolve `end()` quando a faixa é vazia, e desreferenciar isso é comportamento indefinido. A comparação com `end()` não é cerimônia.

cppsrc/inventario.cpp · o iterador de fim não é elemento
const componente* inventario::mais_pesada() const {
  const auto it = std::max_element(
      pecas_.begin(), pecas_.end(),
      [](const std::unique_ptr<componente>& a, const std::unique_ptr<componente>& b) {
        return a->massa() < b->massa();
      });
  return it == pecas_.end() ? nullptr : it->get();
}
